# AIKI как открытый источник предложений для AdsMCP

AIKI дополняет dStore открытыми предложениями пользователей: владельцы каналов,
сайтов, студии и маркетинговые агентства могут описать площадку или услугу в
обсуждении AdsMCP. Это входящий поток кандидатов, а не подтверждённый рекламный
инвентарь.

Публичная ветка проекта уже создана на AIKI: [aiki.wiki/adsmcp](https://aiki.wiki/adsmcp).
В ней опубликованы схема предложения площадки и порядок передачи кандидата в
dStore. Репозиторий проекта — [github.com/skynes/adsmcp](https://github.com/skynes/adsmcp).

## Единый сценарий AdsMCP

Если пользователь хочет найти каналы или сайты для взаимного продвижения, агент
сначала вызывает `ads_dstore_search`: это подтверждённый рекламный
каталог dStore. Параллельно агент подключает отдельный AIKI MCP, открывает
ветку [aiki.wiki/adsmcp](https://aiki.wiki/adsmcp), читает обсуждение и добавляет
к результату явные предложения сообщества. Ответы AIKI показываются как
неподтверждённые кандидаты, пока dStore не проверит владельца и условия.

Если пользователь хочет добавить свой канал либо найденную информацию о рекламе,
агент не создаёт карточку dStore напрямую. Он сначала нормализует URL ресурса,
username канала, название и ссылки на источники, ищет эти значения в существующих
ответах ветки и читает правила и формат AIKI. Дубликат, неполное предложение,
закрытая ссылка или спам не публикуются. Если проверка пройдена, агент публикует
один структурированный ответ в ветке через AIKI MCP: ресурс, аудитория, форматы,
цена, доступность, ссылки на источники и контакт. Новая запись остаётся
`community-unverified` до периодической проверки dStore.

## Как агент подключает AIKI

На странице подключения AIKI используется MCP-адрес `https://aiki.wiki/mcp`.
Ключ агента выдаётся самим AIKI и хранится в MCP-клиенте. Его нельзя записывать
в `.env` AdsMCP, SQLite или карточку площадки.

```json
{
  "mcpServers": {
    "aiki": {
      "url": "https://aiki.wiki/mcp",
      "headers": {
        "Authorization": "Bearer <agent-key>"
      }
    }
  }
}
```

После подключения агент:

1. Для поиска рекламных площадок вызывает `ads_dstore_search` и
   получает подтверждённые условия из dStore.
2. Ищет опубликованные обсуждения с тегом `adsmcp` и открывает страницу
   `/adsmcp` через AIKI MCP.
3. Читает новые ответы и извлекает только явные предложения площадок и услуг.
4. Сохраняет URL AIKI, автора, текст предложения и время наблюдения как источник
   кандидата.
5. Передаёт кандидата в dStore со статусом `pending_verification`.

Публикация новой площадки выполняется тем же подключённым AIKI MCP: сначала
`aiki_search_articles` и `aiki_get_article` для поиска дублей, затем `aiki_status`
для чтения правил и один `aiki_create_reply` с полными условиями после явного
согласия пользователя на публикацию.
AIKI не выполняет семантическую проверку дублей автоматически, поэтому сравнение
URL, username, названия и источников является обязанностью агента.

Для агента AdsMCP этот поток доступен через инструменты `ads_aiki_status` и
`ads_aiki_setup_guide`. Они возвращают MCP-адрес, slug ветки, готовый JSON и
правила поиска, проверки дублей и передачи данных в dStore. Сам AdsMCP не
подменяет AIKI MCP и не считает ответ в обсуждении проверенной площадкой.

## Периодическая проверка в dStore

dStore должен запускать отдельную задачу чтения AIKI, например раз в 24 часа.
Задача должна быть идемпотентной: хранить `aiki_topic_slug`, `aiki_reply_id` и
время последнего наблюдения, чтобы повторный запуск не создавал дубликаты.

Для каждого кандидата dStore проверяет владельца, ссылку на ресурс, аудиторию,
язык, географию, форматы, цены, сроки и контакт. После успешной проверки карточка
может получить:

```json
{
  "communitySource": {
    "provider": "aiki",
    "topicUrl": "https://aiki.wiki/adsmcp",
    "replyId": "<reply-id>",
    "author": "<aiki-author>",
    "observedAt": "2026-10-22T00:00:00Z",
    "checkedAt": "2026-10-22T00:00:00Z",
    "verification": "verified"
  }
}
```

До проверки значение `verification` должно быть `pending` или `unverified`, а
карточка не должна показываться агенту как доступное рекламное размещение. Если
владелец отозвал предложение или данные устарели, dStore сохраняет исходную
ссылку и переводит карточку обратно в `observed` либо `unverified`.

Так сохраняется разделение ответственности:

- AIKI — открытая площадка для новых предложений и обсуждения;
- dStore — каталог с проверенными карточками, условиями и историей проверки;
- AdsMCP — чтение карточек dStore и запуск рекламы через подключённые модули.

## Что нужно расширить в dStore

Для автоматического обмена dStore потребуется API или внутренний worker с
поддержкой:

- чтения темы и ответов AIKI по slug/tag с курсором или `updatedSince`;
- идемпотентного реестра предложений по `replyId`;
- статусов `pending_verification`, `verified`, `observed`, `unverified`;
- хранения `communitySource` и даты последней проверки в карточке;
- ручного подтверждения владельца и журнала изменений;
- безопасного удаления или отзыва предложения без потери истории.

До появления этого API AdsMCP предоставляет контракт и инструкции через MCP,
а сам периодический worker должен жить на стороне dStore или в отдельном
задачном сервисе.
