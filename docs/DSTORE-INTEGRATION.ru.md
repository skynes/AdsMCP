# Интеграция AdsMCP и dStore

Этот документ фиксирует первый рабочий слой интеграции и контракт, который нужно будет расширить на стороне dStore. Цель — чтобы AI-агент через AdsMCP мог найти подходящую площадку, увидеть условия размещения, подготовить предложение и передать его на согласование владельцу ресурса.

Открытые предложения сообщества приходят параллельно через AIKI. Их поток и
правила периодической проверки описаны в [AIKI-интеграции](./AIKI-INTEGRATION.ru.md);
до подтверждения владельца такие предложения не считаются карточками каталога.

## Что уже работает в AdsMCP

AdsMCP подключает публичную карточку dStore как источник данных. Доступ к рекламным кабинетам, локальным кампаниям и секретам при этом остаётся в AdsMCP и не передаётся в dStore.

Новые MCP-инструменты:

- `ads_dstore_status` — показывает адрес и режим адаптера;
- `ads_dstore_search` — ищет подтверждённые рекламные размещения по теме,
  платформе, языку, региону и формату;
- `ads_dstore_card_get` — читает одну карточку по числовому ID или URL карточки;
- `ads_dstore_cards_get` — читает до 50 карточек за один вызов и возвращает частичные ошибки.

По умолчанию AdsMCP читает `https://dstore.one/{id}.json`, а поиск рекламных
условий выполняет через `https://db.dstore.one/api/v1/catalog/placements`.
Адреса можно заменить для локальной разработки через `ADS_DSTORE_BASE_URL` и
`ADS_DSTORE_CATALOG_URL`, таймаут — через `ADS_DSTORE_TIMEOUT_MS`.

## Публичные рекламные условия без кабинета владельца

dStore автоматически собирает карточки из открытых источников, поэтому AdsMCP
не ожидает приватный кабинет или токен владельца. Рекламные условия считаются
данными каталога только вместе с открытой ссылкой, которую может открыть любой
посетитель: постом/описанием Telegram, media kit на `fork.page` или
`telegra.ph`, публичным Google Doc, страницей биржи или другой публичной
страницей.

Команда `/ads` в Telegram-боте — удобный способ показать условия владельцу,
но для автосбора ответ должен быть публично доступен или содержать ссылку на
публичный пост/документ. Личный ответ бота без открытой ссылки не является
источником каталога.

Для каждого источника dStore сохраняет `url`, `foundAt` и `checkedAt`:

- `official` — официальный ресурс или media kit, на который ссылается сам ресурс;
- `third_party` — чужая публичная страница с явной атрибуцией ресурса;
- `unverified` — чужой домен без подтверждённой связи с ресурсом.

Приоритет: `official > third_party > unverified`. `unverified` можно сохранить
как находку, но AdsMCP не должен считать его активным рекламным инвентарём.
Если официальный источник появится позже, он заменяет стороннюю цену, а
сторонние ссылки остаются в `sources[]` как история проверки.

Текущий JSON dStore уже подходит для базовой карточки:

```json
{
  "id": 46125,
  "title": "Котейная тележка",
  "url": "https://t.me/catheyco",
  "icon": "https://cdn.dstore.one/icons/46125.png",
  "platform": "telegram",
  "tags": [],
  "description": "...",
  "useCase": "...",
  "lang": ["ru"],
  "advertising": {
    "schemaVersion": "1.0",
    "status": "available",
    "source": {
      "url": "https://telegra.ph/example-media-kit-10-22",
      "authority": "official",
      "foundAt": "2026-10-22T00:00:00Z",
      "checkedAt": "2026-10-22T00:00:00Z"
    },
    "placements": [
      {
        "id": "post-24h",
        "format": "post",
        "pricingModel": "fixed",
        "price": 15000,
        "currency": "RUB",
        "availability": "unknown",
        "sourceText": "Пост 24 часа — 15 000 RUB"
      }
    ]
  }
}
```

AdsMCP не угадывает ID, не парсит HTML dStore и не передаёт пользовательские
токены: поиск идёт через публичный API рекламного каталога.

## Публичный API рекламного каталога dStore

### 1. Стабильный публичный API каталога

Помимо карточки `/{id}.json`, dStore предоставляет версионируемый API:

```text
GET /api/v1/catalog/placements?q=котики&platform=telegram&lang=ru&region=RU&limit=50&cursor=...
GET /api/v1/catalog/placements/{id}
GET /api/v1/catalog/manifest
```

Ответ списка должен быть постраничным и содержать курсор:

```json
{
  "schemaVersion": "1.0",
  "generatedAt": "2026-10-21T00:00:00Z",
  "revision": "catalog-revision",
  "items": [],
  "nextCursor": null
}
```

Это позволит AdsMCP искать по теме и аудитории, не загружая весь каталог и не повторяя внутреннюю логику сайта dStore.

`GET /api/v1/catalog/placements/{id}` возвращает только карточку с публичным
источником и ценой. В ответе сохраняются `source`, `sources[]`,
`verification.status`, `foundAt`/`checkedAt`, `pricingModel`, `unit` и
`sourceUrl` конкретного размещения. AdsMCP может безопасно использовать
`status: available` только для `official` или явно атрибутированного
`third_party`; `unverified` нужно показывать как неподтверждённую находку.

### 2. Модель рекламной площадки

Карточка приложения и рекламный инвентарь — разные сущности. Для площадки нужны стабильные поля:

```json
{
  "id": 46125,
  "resourceUrl": "https://t.me/catheyco",
  "title": "Котейная тележка",
  "description": "...",
  "icon": "https://cdn.dstore.one/icons/46125.png",
  "platform": "telegram",
  "categories": ["gaming", "video"],
  "languages": ["ru"],
  "regions": ["RU"],
  "audience": {
    "subscribers": 120000,
    "avgReach": 42000,
    "avgViews": 38000,
    "engagementRate": 0.064,
    "audienceAge": {"18-24": 0.31, "25-34": 0.44},
    "audienceGender": {"female": 0.38, "male": 0.62}
  },
  "placements": [
    {
      "id": "placement-1",
      "format": "native_post",
      "pricingModel": "fixed",
      "price": 25000,
      "currency": "RUB",
      "minOrder": 1,
      "availability": "available",
      "leadTimeHours": 48
    }
  ],
  "contact": {"type": "dstore_relay"},
  "verification": {
    "status": "verified",
    "checkedAt": "2026-10-21T00:00:00Z",
    "method": "owner_claim"
  },
  "updatedAt": "2026-10-21T00:00:00Z"
}
```

Цифры аудитории должны быть агрегированными. Личные данные подписчиков, токены рекламных кабинетов и переписки в этот API не попадают.

### 3. Поиск, фильтры и сортировка

Минимальный набор параметров:

- `q` — поиск по названию, описанию и тегам;
- `platform` и `channelType` — Telegram, сайт, YouTube, блог и т. п.;
- `lang`, `region`, `category`;
- `minReach`, `maxReach`, `minEngagement`;
- `format`, `pricingModel`, `currency`, `availableFrom`;
- `sort=relevance|reach|engagement|price|updated`;
- `limit` и непрозрачный `cursor`.

### 4. Почему отдельный кабинет владельца пока не нужен

Пользователь может оставить в описании ресурса короткую ссылку на media kit,
страницу `fork.page`/`telegra.ph`, публичный Google Doc или контакт менеджера.
dStore сам проверяет страницу и сохраняет доказательство. Подтверждение
владельца можно добавить позже как удобный механизм подачи ссылки, но оно не
должно превращать непубличные данные в inventory и не должно повышать статус
`unverified` без открытой атрибуции.

### 5. Рабочий процесс взаимного продвижения

Поиск площадки и покупка рекламы — разные действия. dStore нужно описать отдельные сущности:

```text
POST /api/v1/proposals
GET  /api/v1/proposals/{id}
POST /api/v1/proposals/{id}/accept
POST /api/v1/proposals/{id}/decline
```

Предложение должно содержать `placementId`, `campaignRef`, формат, текст или ссылку на материалы, сроки, цену и статус. AdsMCP создаёт только черновик или предложение после явного подтверждения пользователя; окончательное принятие остаётся за владельцем площадки в dStore.

Для взаимного продвижения можно добавить `exchange`, где цена равна встречному размещению, но условия, объём и сроки всё равно фиксируются как отдельные позиции.

### 6. Синхронизация без полного скачивания

Нужен манифест изменений:

```text
GET /api/v1/catalog/manifest?since=2026-10-21T00:00:00Z
```

Он должен возвращать `revision`, `updated`, `removed`, `nextCursor` и `generatedAt`. Желательны `ETag`, `Last-Modified`, `Cache-Control` и поддержка `If-None-Match`. Это позволит AdsMCP кэшировать каталог локально и обновлять только изменившиеся карточки.

### 7. Ошибки и ограничения

API стоит зафиксировать через OpenAPI или JSON Schema. Нужны единые ответы `400`, `401`, `403`, `404`, `409`, `429`, `5xx`, поле `requestId`, понятный `retryAfter` для `429` и лимиты запросов в заголовках. CORS для публичного чтения не заменяет авторизацию записи.

## План подключения

1. **Сейчас:** AdsMCP читает `/{id}.json`, сохраняет `advertising` и нормализует
   источники/цены через MCP-инструменты.
2. **Следующий шаг:** использовать `manifest` и `catalog/placements` для
   локального кэша и поиска площадок без полного скачивания каталога.
3. **Позже:** добавить необязательный owner claim, предложения размещения и
   согласование взаимного продвижения; открытая ссылка всё равно остаётся
   источником рекламных условий.

До появления этих endpoint AdsMCP не должен считать карточку доступным рекламным инвентарём только потому, что у неё есть `title` и `url`: условия, аудитория и статус подтверждения должны приходить из отдельной модели dStore.
