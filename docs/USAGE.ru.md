# Руководство пользователя AdsMCP

[← README](../README.ru.md) · [Вся документация](./README.ru.md)

Установка и конфигурация MCP-клиента описаны в [быстром старте](../README.ru.md#быстрый-старт).
Здесь — настройки после установки и основные инструменты для работы.
Все команды выполняются из корня репозитория; примеры копирования файлов — для PowerShell.

## Конфигурация и локальные данные

Если нужен файл настроек `.env`, создайте его из примера (если его ещё нет):

```powershell
Copy-Item .env.example .env
```

Главная настройка — каталог локальных данных:

```dotenv
ADS_MCP_DATA=./data
```

`ADS_MCP_DATA` — единый локальный корень данных для всех модулей AdsMCP. Если
переменная не задана, используется `./data`. Модули не должны создавать
параллельное состояние рядом с исходниками, в `server/data` или в отдельных
каталогах интеграций.

Структура по умолчанию:

```text
data/
  ads.db
  clickru-settings.json
  microsoft-ads-settings.json
  telegram/                  # сессии аккаунта Telegram и файлы TDLib
  browser-profiles/          # постоянные профили браузера для площадок
  yandex-direct/             # журнал и лимиты провайдера
  network/                   # состояние опционального Relay
  logs/                      # локальная диагностика
  secrets/                   # токены, ключи и сохранённые сессии
```

Для нестандартного корня лучше использовать абсолютный путь вне репозитория.
Если используется относительный путь внутри репозитория, добавьте именно его в
`.gitignore` до размещения там ключей доступа или состояния интеграций.

Корневой `.env` не попадает в Git. В нём можно задавать ключи доступа,
если модуль получает их через переменные окружения. Сессии OAuth, cookies,
закрытые ключи, журналы, профили браузера и базы хранятся внутри `ADS_MCP_DATA`.
Секреты нельзя помещать в `modules/modules.json`, исходники или записи SQLite.

`data/`, `.env`, локальные копии внешних модулей, виртуальные окружения,
профили браузера, базы, ключи и сгенерированные архивы исключены в
[`.gitignore`](../.gitignore). Реальные ключи доступа и сессии должны оставаться
локальными.

## Локальная панель

Попросите агента вызвать `ads_dashbord_start` и откройте возвращённый локальный
адрес. Панель помогает подключать аккаунты и проверять настройки интеграций.
Инструкции для отдельных площадок собраны в [руководстве по интеграциям](./INTEGRATIONS.ru.md).

Локальная панель поддерживает английский и русский. Переключатель языка сохраняет
выбор; пункт **Язык браузера** использует `Accept-Language`. Если язык не указан
или не поддерживается, панель открывается на английском.

## Внешние MCP-модули

Если локального манифеста ещё нет, создайте его из шаблона:

```powershell
Copy-Item modules/modules.example.json modules/modules.json
```

Манифест поддерживает:

- локальные stdio-модули и удалённые Streamable HTTP-модули;
- рабочие каталоги относительно корня репозитория;
- подстановки переменных окружения, например `${ENV_NAME}`;
- `inherit_env` — список переменных, которые можно передать модулю;
- `allow_tools` — список разрешённых инструментов модуля.

Проверить настройки модулей без их запуска можно через `ads_module_plan`.
Список доступных инструментов возвращает `ads_module_tools`,
а `ads_module_call` вызывает инструмент с учётом списка разрешений.

Для интерактивной настройки откройте локальный dashboard через
`ads_dashbord_start` и перейдите на страницу **Модули**. Она показывает, какие
модули есть в `modules/modules.json`, какую команду/runtime они используют,
какие обязательные credentials заполнены, откуда взято значение (`.env` или
локальный vault) и прошёл ли последний MCP handshake. Полные значения токенов
никогда не возвращаются в браузер.

Credentials, сохранённые через dashboard, лежат в
`ADS_MCP_DATA/secrets/module-secrets.json` с ограниченными правами файловой
системы (на Windows доступ регулируется ACL каталога). В форме можно
сохранить значения для конкретного модуля; пустые поля не затирают уже сохранённые
секреты. Кнопка **Проверить runtime** запускает только `tools/list`, не вызывает
provider write-инструменты и не отправляет письма/рекламу.

Выбор модулей и ограничения описаны в [обзоре провайдеров](./PROVIDER-MODULES.md).
Подобрать площадку до настройки доступа помогает
[руководство по аудитории и каналам](./PLATFORM-GUIDE.md).

## Основные MCP-инструменты

| Группа | Примеры | Назначение |
| --- | --- | --- |
| Проекты | `ads_project_create`, `ads_project_list`, `ads_project_analytics` | Группировка кампаний и показатели проекта |
| Кампании | `ads_campaign_create`, `ads_campaign_update`, `ads_campaign_list` | Локальные записи кампаний |
| События и расходы | `ads_event_ingest`, `ads_spend_record` | Конверсии и метрики площадок без повторных записей |
| Аналитика | `ads_campaign_analytics`, `ads_campaign_timeseries` | Показатели и их изменение во времени |
| Атрибуция | `ads_attribution_report` | Вклад касаний с рекламой в конверсии |
| Интеграции | `ads_integration_plan`, `ads_platform_guide` | Проверка готовности и выбор площадки |
| Модули | `ads_module_plan`, `ads_module_tools`, `ads_module_call` | Работа с внешними MCP-модулями |
| Синхронизация | `ads_google_ads_sync`, `ads_yandex_direct_sync`, `ads_telegram_ads_sync` | Импорт в локальную SQLite |
| Автоматизация | `ads_automation_rule_create`, `ads_automation_run` | Правила по показателям и пробный запуск |
| Хранилище | `ads_store_status` | Состояние локальной базы |

Собственные инструменты площадок также доступны через мост модулей,
если они включены в список разрешённых инструментов (`allow_tools`).

Для почты модуль `email` использует IMAP для проверки входящих сообщений и SMTP
для отправки. Добавьте в `.env` `MCP_EMAIL_ADDRESS`, `MCP_EMAIL_PASSWORD`,
`MCP_EMAIL_IMAP_HOST` и `MCP_EMAIL_SMTP_HOST`; остальные параметры являются
необязательными. Перед отправкой письма запрос должен получить явное подтверждение
пользователя. Список разрешений и альтернативы собраны в
[решении по Email MCP](./decisions/0016-email-smtp-imap-mcp.md).

Атрибуция поддерживает модели `first_touch`, `last_touch`, `linear` и
`position_based`. О связях между проектами, кампаниями и событиями см.
[карту базы данных](./DATA-MODEL.ru.md).

Импорт читает данные рекламного кабинета и сохраняет их локально. Автоматизация
сначала выполняется в `dry-run`; для исполнения нужен `execute=true`.
Поддерживаемые операции изменения на площадках требуют отдельных подтверждений.
Подробнее — [модель безопасности](./ARCHITECTURE.md#safety-defaults).

## Опциональный Ads Network Relay

Relay нужен для каталогов рекламных мест, взаимодействия участников и обмена
агрегированными данными. Локальный MCP работает без него.
Если отдельный репозиторий Relay установлен в `server/`:

```powershell
npm run build:server
npm run start:server
```

Клиенту задаётся `ADS_NETWORK_URL`. Для закрытых операций нужен одинаковый
`ADS_NETWORK_WRITE_TOKEN` на клиенте и сервере. Relay получает только данные,
явно отправленные сетевыми инструментами; ключи доступа, исходные локальные
события и действия с кампаниями остаются локальными.
