# Разработка AdsMCP

[← README](../README.ru.md) · [Вся документация](./README.ru.md)

## Требования

- Node.js `>=22.5` — проект использует встроенный runtime `node:sqlite`.
- Python нужен только для внешних модулей, которым он необходим.
- MCP-клиент: Cursor, Claude Desktop или другой клиент со stdio.

После установки зависимостей через `npm install` сервер можно запустить
в режиме разработки командой `npm run dev`, а собранную версию — `npm start`.
Обе команды запускают MCP-сервер по stdio.

## Структура репозитория

```text
src/        TypeScript MCP-сервер, хранилище, адаптеры и инструменты
scripts/    smoke-тесты, вход в Telegram и вспомогательные скрипты
build/      исходники статического сайта из .openai/hosting.json
docs/       руководства, архитектура и решения по интеграциям
modules/    шаблон манифеста и локальные копии внешних модулей
data/       единый корень ADS_MCP_DATA для баз, секретов и состояния
server/     опциональный Ads Network Relay; отдельный репозиторий
```

В Git хранится только шаблон манифеста провайдеров. `modules/modules.json` и
копии репозиториев в `modules/*/` остаются локальными и игнорируются.

## Устройство сервера

Основной MCP-сервер работает по stdio. Внешние модули подключаются по stdio
или Streamable HTTP. Их API-логика выполняется вне локального хранилища AdsMCP,
а учётные данные не записываются в SQLite.

Границы компонентов и поток данных описаны в [архитектуре](./ARCHITECTURE.md),
структура SQLite — в [карте базы](./DATA-MODEL.ru.md).
Для работы с интеграциями см. [выбор провайдеров](./PROVIDER-MODULES.md),
[структуру модулей](../modules/README.md) и [архитектурные решения](./decisions/).

## Команды

```powershell
npm run dev               # локальный TypeScript MCP-сервер
npm run typecheck:mcp     # проверка типов MCP-сервера
npm run build:mcp         # сборка MCP-сервера
npm run typecheck         # проверка типов MCP-сервера
npm run build             # сборка MCP-сервера
npm run typecheck:all     # проверка типов MCP и Relay (нужен server/)
npm run build:all         # сборка MCP и Relay (нужен server/)
npm run build:server      # только Relay (нужен server/)
npm run smoke             # сборка, smoke и проверка защиты панели настроек
npm run smoke:network     # сборка и проверка Relay (нужен server/)
npm run check:publication # проверка на приватные файлы и секреты
```

Корневого `npm test` нет. У внешних модулей свои тесты и инструкции.

Состав публичных исходников и проверки перед публикацией описаны в
[руководстве по публикации](./PUBLISHING.md).

## Правило правок и предложения в `main`

Если пользователь или агент нашёл улучшение, более сильный provider-модуль или
исправление, его нужно оформить отдельным связным change set:

1. создать ветку `codex/<краткая-тема>` от актуального `main`;
2. сохранить правки в одном или нескольких понятных коммитах;
3. выполнить соответствующие typecheck/build/smoke-проверки и проверить diff;
4. предложить ветку в `main` через Pull Request.

Прямые коммиты в `main` не используются. Если GitHub credentials или fork ещё
не настроены, коммит всё равно сохраняется локально, а пользователю сообщаются
ветка, commit и оставшийся шаг публикации PR. Существующие пользовательские
правки нельзя перезаписывать или включать в коммит без явного согласования.
