# 🎯 AdsMCP

**Управляйте рекламой через AI-агента и держите данные у себя, бесплатно.**

AdsMCP — локальный MCP-сервер, который объединяет рекламные кампании, расходы
и аналитику в одном интерфейсе для агента. Подключайте нужные площадки,
сравнивайте результаты и сокращайте рутину.

Наша цель — сделать рекламу простой: от изучения аудитории до запуска и
оптимизации через привычный чат, под вашим контролем.

> Ранняя версия `0.1.0`: локальное ядро работает, возможности интеграций различаются.
> Полный рекламный цикл через агента — в планах развития.

## Что уже умеет

- **Собирать данные:** проекты, кампании, расходы и конверсии в локальной SQLite.
- **Считать результат:** CTR, CPC, CPA, ROAS и вклад каналов в конверсии.
- **Подключать площадки:** импорт из Google Ads, Яндекс Директа, Telegram Ads
  и Microsoft Advertising после настройки соответствующих интеграций.
- **Работать с сообществами:** коннекторы Telegram, Discord и Mastodon
  для поиска контекста и общения с учётом правил канала.
- **Автоматизировать под контролем:** сначала пробный запуск (`dry-run`),
  внешние действия — с явным подтверждением.

Для первой локальной установки достаточно MCP-сервера. Интеграции подключаются
по мере необходимости; рекламные кабинеты и доступ к ним настраиваются отдельно.

## Интеграции: что готово и что в планах

Статус показывает возможности проекта после настройки аккаунтов и модулей.
Изменения на площадках требуют явного подтверждения.

| Интеграция | Готовность | Что доступно и какие ограничения |
| --- | --- | --- |
| Google Ads | ✅ Импорт и отдельные действия | Отчёты и статистика в SQLite; изменения через API Agent с подтверждением. |
| Яндекс Директ | ✅ Импорт и отдельные действия | Статистика, изменения и создание кампании с выключенными показами; удаление закрыто. |
| Telegram Ads | ✅ Импорт и управление объявлениями | Отчёты, создание, бюджет, модерация и пауза через официальный API. |
| Microsoft Advertising / Bing | ✅ Только чтение | Кампании, отчёты и импорт статистики; изменение кампаний не включено. |
| Аккаунт Telegram | ✅ Поиск и общение | Поиск по чатам и личные/публичные ответы; действуют требования Premium и лимиты. |
| Discord | ✅ Бот-коннектор | Поиск и публикация в доступных боту каналах разрешённых серверов. |
| Mastodon | ✅ Аккаунт и общение | OAuth, чтение упоминаний, ответы и изменение профиля. |
| CRM / Webhook | ✅ Приём событий | Загрузка переданных конверсий; управление CRM не реализовано. |
| dStore | 🟢 Рекламный каталог | `ads_dstore_search` ищет подтверждённые публичные условия размещения, а `ads_dstore_card_get` читает карточки. |
| AIKI | 🟡 Источник предложений | Для поиска агент читает ветку AdsMCP через отдельный AIKI MCP; для добавления площадки сначала проверяет повторы и правила ветки, затем публикует структурированный ответ на AIKI. |
| VK Ads через Click.ru | 🟡 Нужен ручной шаг | Подключён брокер для чтения; нужна первичная привязка кабинета VK. |
| Avito Ads | 🟡 Готов модульный путь | Официальный Avito Ads API через локальный read-only allowlist. |
| Apple Search Ads | 🟡 Шаблон подключения | Настроен путь к внешнему MCP для чтения; локального импорта в SQLite пока нет. |
| TikTok Ads | 🟡 Готов модульный путь | Локальный MCP к TikTok Business API, только чтение по allowlist. |
| Reddit Ads | 🟡 Шаблон подключения | Подготовлено подключение внешнего MCP для кампаний и отчётов, только чтение. |
| Meta Ads | 📋 В планах | Описан контракт адаптера; подключение Graph API ещё не реализовано. |
| OpenAI Ads / ChatGPT | 📋 Кандидат | Нужно подтвердить доступность API и модель рекламного кабинета. |
| Spotify Ads | 📋 Кандидат | Подключение API и отчётов ещё не реализовано. |
| X Ads | 📋 Кандидат | Нужно проверить доступ к API и требования к рекламному кабинету. |

## Быстрый старт

Понадобятся **Node.js 22.5+** и MCP-клиент с поддержкой stdio, например Cursor
или Claude Desktop. В каталоге скачанного репозитория выполните:

```sh
npm install
npm run build:mcp
```

Добавьте сервер в конфигурацию MCP-клиента, заменив путь на свой:

```json
{
  "mcpServers": {
    "ads-mcp": {
      "command": "node",
      "args": ["C:/path/to/AdsMCP/dist/index.js"]
    }
  }
}
```

Клиент сам запустит сервер. Для проверки попросите агента проверить всё ли в порядке и можем ли начинать?
Данные по умолчанию хранятся в `data/` внутри репозитория.

Перед рабочим использованием прочитайте [правила бесплатного использования](./docs/FREE-USE-RULES.md)
через `ads_free_use_rules` и примите текущую версию инструментом
`ads_free_use_accept` с `confirm=true`. Принятие хранится только в локальном
каталоге `ADS_MCP_DATA`.

### Обновления с GitHub

При запуске AdsMCP проверяет GitHub не чаще одного раза в сутки. Репозиторий
определяется из локального `origin`, либо его можно указать в `.env` через
`ADSMCP_UPDATE_REPOSITORY=owner/repository`. Новый релиз или тег скачивается в
`ADS_MCP_DATA/updates/`; работающая установка и учетные данные не перезаписываются.
Проверку можно отключить через `ADSMCP_UPDATE_ENABLED=false`.

Раз в неделю AdsMCP проверяет локальный Git и видит правки пользователя или
установленного модуля. Пароли, локальные данные, сборку и игнорируемые файлы он
не публикует. Правки только в общих рекомендациях могут отправляться в PR
автоматически после настройки GitHub. Правки кода, модулей, документации или
конфигурации сначала показываются инструментом `ads_github_contribution_status`,
а публикация выполняется отдельным вызовом
`ads_github_contribution_create_pr` с `confirm=true`.

Для публикации укажите `ADSMCP_UPSTREAM_REPOSITORY`, личный
`ADSMCP_FORK_REPOSITORY` и fine-grained `ADSMCP_GITHUB_TOKEN`, затем вызовите
`ads_github_contribution_setup`. Fork не нужен для обычной локальной работы; он
нужен перед отправкой PR. Еженедельную проверку можно отключить через
`ADSMCP_WEEKLY_PR_ENABLED=false`.
